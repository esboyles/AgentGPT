# Claude Code Now Anchors Obsidian-Backed Jarvis Assistants

The state-of-the-art "Jarvis" built on Claude and Obsidian in late 2026 is not a product but a stack: **Claude Code launched at the root of a git-backed Obsidian vault**, steered by a root `CLAUDE.md` under 200 lines, taught Obsidian syntax by Steph Ango's `obsidian-skills` (**49.4k stars**), given index-aware vault access through the **official Obsidian CLI shipped in Obsidian 1.12 (February 2026)**, and wrapped in Anthropic's own first-party assistant pieces that arrived during 2026: Channels (Telegram, Discord, iMessage), Markdown auto memory, three tiers of scheduling (`/loop`, Desktop scheduled tasks, cloud Routines) and Remote Control from the phone app ([Obsidian CLI docs](https://github.com/obsidianmd/obsidian-help/blob/master/en/Extending%20Obsidian/Obsidian%20CLI.md); [kepano/obsidian-skills](https://github.com/kepano/obsidian-skills); [Claude Code channels docs](https://code.claude.com/docs/en/channels)). OpenClaw (**~392k GitHub stars**) remains the dominant general-purpose harness and set the de facto Markdown memory conventions (`SOUL.md`, `MEMORY.md`, `memory/YYYY-MM-DD.md`, heartbeat plus cron), but Anthropic's ban on using claude.ai subscriptions inside third-party harnesses, plus OpenClaw's 2026 security record, push Claude-centric builders toward Claude Code itself, NanoClaw (the Agent SDK harness), or a thin Telegram bot over a persistent Claude Code session ([openclaw/openclaw](https://github.com/openclaw/openclaw); [OpenClaw Anthropic provider docs](https://raw.githubusercontent.com/openclaw/openclaw/main/docs/providers/anthropic.md)). Memory architecture has converged across every serious design on the same shape, a small bootstrap index read first, dated append-only logs, and nightly consolidation into curated notes, with Karpathy's April 2026 "LLM Wiki" gist as the most-copied blueprint and grep-style retrieval sufficient until vaults reach a few thousand notes, where one measured build shows paraphrase recall dropping to **77%** without embeddings ([Karpathy gist](https://gist.github.com/karpathy/442a6bf555914893e9891c11519de94f); [obsidian-second-brain](https://github.com/eugeniughelbur/obsidian-second-brain)). Voice remains the weakest first-party layer (Claude Code `/voice` is dictation-only and streams audio to Anthropic), so builders bolt on local Whisper/Parakeet plus Kokoro/Piper or cloud ElevenLabs/Fish Audio. Running costs cluster at a **$20–200/month Claude subscription plus $0–6/month hosting**, and the security playbook, Tailscale-only access, sender allowlists, scoped permissions enforced by hooks rather than prose, git as the undo layer, was written largely in response to OpenClaw's tens of thousands of exposed gateways and malicious-skill audits. There is still no first-party Anthropic–Obsidian connector; everything below is assembled from community parts and Anthropic primitives that happen to operate on plain folders.

## Five wiring patterns link Claude to a vault, and CLI-plus-skills is now the default

Because an Obsidian vault is a folder of Markdown, the baseline integration needs no integration at all: open a terminal in the vault, run `claude`, and use `/init` to generate a starter `CLAUDE.md`. Claude Code's memory system loads `CLAUDE.md` from the working directory and every parent at launch, loads subdirectory `CLAUDE.md` files on demand when Claude touches a file there, discovers `.claude/rules/*.md` recursively with optional `paths:` scoping, and officially targets **under 200 lines per CLAUDE.md** because "longer files consume more context and reduce adherence" ([Claude Code memory docs](https://code.claude.com/docs/en/memory)). Kenneth Reitz's widely cited March 2026 essay runs exactly this way on a 467-note, iCloud-synced vault, treating the root file as "an API contract" that states purpose, conventions and prohibitions such as "Do not create new files unless explicitly asked" and "Do not restructure existing folder hierarchies" ([Reitz essay source](https://github.com/kennethreitz/kennethreitz.org/blob/main/data/essays/2026-03-06-obsidian_vaults_and_claude_code.md)). The one instruction every guide now adds is a wikilink rule, because Claude Code defaults to standard Markdown links and agent-written notes otherwise fall out of the graph; one guide calls it "the single instruction most setups forget" ([codewithseb](https://www.codewithseb.com/blog/claude-code-obsidian-second-brain-guide); [xda-developers](https://www.xda-developers.com/added-one-thing-to-claude-obsidian-setup-and-wikilinks-stopped-breaking/)). kepano's `obsidian-skills` packages that knowledge as Agent Skills (`obsidian-markdown`, `obsidian-bases`, `json-canvas`, `obsidian-cli`, `defuddle`, `knap`), installable with `/plugin marketplace add kepano/obsidian-skills` then `/plugin install obsidian@obsidian-skills`, and is "documentation, not code" with no network calls ([kepano/obsidian-skills](https://github.com/kepano/obsidian-skills)). Notably, Anthropic documents nothing Obsidian-specific: the connector directory shows no Obsidian entry and a code search of `anthropics/claude-code` for "obsidian" returns zero hits, so the Obsidian CEO's skills repo is the closest thing to an official bridge ([claude.com/connectors](https://claude.com/connectors); [GitHub code search](https://github.com/search?q=obsidian+repo%3Aanthropics%2Fclaude-code&type=code)).

The second pattern, the official Obsidian CLI, changed what "state of the art" means in February 2026. Obsidian 1.12's release notes introduce "a command line interface that lets you control Obsidian from your terminal for scripting, automation, and integration with external tools"; it requires installer 1.12.7+, must be enabled under Settings → General, needs the app running, and uses `name=value` parameters where `vault=` must come first and `file=` resolves like a wikilink ([v1.12 release notes](https://github.com/obsidianmd/obsidian-help/blob/master/Release%20notes/v1.12.md); [Obsidian CLI docs](https://github.com/obsidianmd/obsidian-help/blob/master/en/Extending%20Obsidian/Obsidian%20CLI.md)). What it gives an agent that grep cannot is the live index: `search`/`search:context`, `daily:append`, `property:set`, `base:query` with JSON/CSV output, `backlinks`, `unresolved`, `orphans`, `deadends`, `sync:status`, and an `eval` command that runs JavaScript inside the app, with developer commands explicitly designed so "agentic coding tools" can test plugins ([Obsidian CLI docs](https://github.com/obsidianmd/obsidian-help/blob/master/en/Extending%20Obsidian/Obsidian%20CLI.md)). The community `Obsidian-CLI-skill` (450 stars) catalogs the operational gotchas: empty output when Obsidian is not running, the wrong vault in multi-vault setups unless `vault=` is first, a broken IPC socket under systemd `PrivateTmp=true` or Snap confinement, and `property:set` storing list values as plain strings ([pablo-mano/Obsidian-CLI-skill](https://github.com/pablo-mano/Obsidian-CLI-skill)). The CLI exposes Bases but not Dataview, which matters because Bases `.base` files are plain YAML an agent can author to produce live database views, whereas Dataview is a UI plugin that no route lets Claude execute directly except aaronsb's in-Obsidian MCP plugin ([kepano obsidian-bases SKILL.md](https://github.com/kepano/obsidian-skills/blob/main/skills/obsidian-bases/SKILL.md); [aaronsb/obsidian-mcp-plugin](https://github.com/aaronsb/obsidian-mcp-plugin)).

The third pattern, MCP, is the route for Claude Desktop (which lacks filesystem access) and for sharing one vault across several agents. The longest-lived option is coddingtonbear's Local REST API plugin (**3,018 stars**, created 2022, still updated October 2026), which since release 4.0.0 ships a built-in Streamable HTTP MCP server at `https://127.0.0.1:27124/mcp/`, registered in Claude Code with `claude mcp add --transport http obsidian https://127.0.0.1:27124/mcp/ --header "Authorization: Bearer <key>"`; Claude Desktop cannot speak HTTP MCP directly and needs the `mcp-remote` bridge in `claude_desktop_config.json` ([obsidian-local-rest-api README](https://github.com/coddingtonbear/obsidian-local-rest-api)). Its security design is worth copying: a self-generated name-constrained CA, `.obsidian` blocked with a 403 unless explicitly enabled, brute-force throttling at ten wrong keys a minute, and signed single-use upload URLs ([obsidian-local-rest-api README](https://github.com/coddingtonbear/obsidian-local-rest-api)). MarkusPfundstein's Python `mcp-obsidian` (**4,471 stars**) sits on that REST API and exposes `patch_content` relative to headings and frontmatter, but needs `mcp>=1.1.0,<2.0.0` or it crashes at import ([MarkusPfundstein/mcp-obsidian](https://github.com/MarkusPfundstein/mcp-obsidian)). For setups where Obsidian need not be running, `bitbonsai/mcpvault` (1,684 stars) works on files directly with a `--read-only` flag, path-traversal and symlink checks, an extension whitelist, and confirmation paths for deletes and moves ([bitbonsai/mcpvault](https://github.com/bitbonsai/mcpvault)). Stavrakis's `obsidian-mcp` README carries the warning every MCP route deserves: "MCP clients can invoke destructive tools... Back up important vaults" ([StevenStavrakis/obsidian-mcp](https://github.com/StevenStavrakis/obsidian-mcp)).

The fourth pattern inverts the relationship and runs Claude Code inside Obsidian. `YishenTu/claudian` (**15,633 stars**, created December 2025, releasing roughly weekly through October 2026) embeds Claude Code or Codex as a sidebar collaborator with the vault as working directory, inline word-level diffs, vault-scoped skills and `@mention` of files; it is desktop-only, requires Obsidian 1.13+, and documents two recurring failures, `spawn claude ENOENT` under nvm/fnm and an inherited `ANTHROPIC_API_KEY` silently overriding subscription login ([YishenTu/claudian](https://github.com/YishenTu/claudian)). `RAIT-09/obsidian-agent-client` (2,447 stars) does the same via Zed's Agent Client Protocol with per-action approve/reject off by default, and Copilot for Obsidian V4 (7.8k stars) connects to an existing Claude Code login rather than a BYOK key ([RAIT-09/obsidian-agent-client](https://github.com/RAIT-09/obsidian-agent-client); [logancyang/obsidian-copilot](https://github.com/logancyang/obsidian-copilot)). A separate family of IDE-protocol bridges (`obsidian-claude-ide`, "Claude Code IDE Pro", "Claude Code Bridge") only expose the open file and selection to Claude Code's `/ide` picker; they solve editor context, not vault semantics, and many setups pair one with the CLI ([petersolopov/obsidian-claude-ide](https://github.com/petersolopov/obsidian-claude-ide)).

The fifth pattern, embedding the Claude Agent SDK or `claude -p` in a custom service, is what most self-described "Jarvis" repos do. Anthropic describes the SDK as "the same tools, agent loop, and context management that power Claude Code," loading skills, commands and memory from `.claude/` exactly like the CLI, with other languages told to shell out to `claude -p --output-format json` ([Agent SDK overview](https://code.claude.com/docs/en/agent-sdk/overview)). Roasbeef's `obsidian-claude-code` plugin builds on the SDK and is desktop-only because the SDK "requires Node.js, which is available in Obsidian's Electron environment but not on mobile" ([Roasbeef/obsidian-claude-code](https://github.com/Roasbeef/obsidian-claude-code)). Finally, Cowork, Anthropic's desktop product for non-developers, gets Obsidian support for free by pointing its folder access at the vault, with no MCP server required and edits appearing live in Obsidian; the companion `cowork-obsidian` plugin warns that `~/.claude/settings.json` does not configure Claude Desktop and forbids vaults inside iCloud/Dropbox/OneDrive folders because syncing "can corrupt vault writes," a claim Reitz's iCloud-synced vault contradicts in practice ([AutomatedMarketer/cowork-obsidian](https://github.com/AutomatedMarketer/cowork-obsidian); [Reitz essay](https://github.com/kennethreitz/kennethreitz.org/blob/main/data/essays/2026-03-06-obsidian_vaults_and_claude_code.md)).

| Route | Needs Obsidian running | Vault semantics (links, properties, daily notes) | Works with | Best for |
|---|---|---|---|---|
| Claude Code at vault root + `obsidian-skills` | No | Via skills (syntax only) and grep | Claude Code, Cowork, Agent SDK | Default; everything else layers on it |
| Official Obsidian CLI | Yes | Full index: search, backlinks, orphans, properties, Bases, daily notes | Any agent with Bash | Idempotent writes, link hygiene, Bases queries |
| Local REST API MCP (v4+) / `mcp-obsidian` | Yes | PATCH by heading/frontmatter, commands, search | Claude Desktop (via `mcp-remote`), Claude Code, other agents | Claude Desktop; multi-agent sharing |
| `mcpvault` / Stavrakis `obsidian-mcp` | No | File-level with validation, BM25 search | Any MCP client | Headless servers, read-only exposure |
| Claudian / Agent Client / Copilot V4 | Yes (desktop) | Editor context, diffs, approvals | Claude Code, Codex, others | Interactive editing inside Obsidian |
| Agent SDK / `claude -p` service | No | Whatever the service implements | Custom bots | Telegram/voice front-ends, overnight batches |

## OpenClaw defined the harness; Claude Code absorbed Channels, memory and schedulers

OpenClaw, Peter Steinberger's project that began as Clawdbot in November 2025, was renamed Moltbot after Anthropic objected that "Clawd" sounded like "Claude" (around 27 January 2026) and became OpenClaw days later, is the reference design for always-on personal agents: **391.7k stars, 82.4k forks, ~108k commits**, releases every few days (2026.10.1 on 10 October 2026), channels for Discord, iMessage, Slack, Teams, Telegram, WhatsApp, Signal "and 20+ more," and models as swappable plugins ([openclaw/openclaw](https://github.com/openclaw/openclaw); [OpenClaw releases](https://github.com/openclaw/openclaw/releases); [alternativeto.net rename coverage](https://alternativeto.net/news/2026/1/trending-open-source-ai-agent-clawdbot-rebrands-to-moltbot-after-pressure-from-anthropic/)). Steinberger joined OpenAI on 15 February 2026 "to lead work on the next generation of personal agents," with OpenClaw moving to a foundation, which is why Claude-first builders now watch the project's provider priorities carefully ([TechCrunch](https://techcrunch.com/2026/02/15/openclaw-creator-peter-steinberger-joins-openai/)). Its architecture is the template everyone else copies: a Gateway process bridges channels; memory is plain Markdown in `~/.openclaw/workspace` (`AGENTS.md` operating instructions, `SOUL.md` persona, `USER.md` preferences, `MEMORY.md` curated facts loaded at session start, `memory/YYYY-MM-DD.md` daily notes indexed for hybrid search but not injected every turn); a "memory flush" turn saves context before compaction; a "Dreaming" background job promotes items into `MEMORY.md` after score, recall-frequency and query-diversity gates; and proactivity comes from a heartbeat (default `30m`, becoming `1h` under Anthropic OAuth auth) plus a separate automations/cron scheduler with `at`, `every`, `cron`, webhook and Gmail Pub/Sub triggers ([OpenClaw memory docs](https://raw.githubusercontent.com/openclaw/openclaw/main/docs/concepts/memory.md); [agent-workspace docs](https://raw.githubusercontent.com/openclaw/openclaw/main/docs/concepts/agent-workspace.md); [heartbeat docs](https://raw.githubusercontent.com/openclaw/openclaw/main/docs/gateway/heartbeat.md); [cron-jobs docs](https://raw.githubusercontent.com/openclaw/openclaw/main/docs/automation/cron-jobs.md)). Obsidian support is official but deliberately separate from the main vault: the bundled `memory-wiki` plugin compiles durable knowledge into a wiki at `~/.openclaw/wiki/main` with `vault.renderMode: "obsidian"` and optional `obsidian.useOfficialCli: true`, and an `obsidian-vault-maintainer` skill favours wikilinks and Dataview-compatible frontmatter; a February 2026 issue asking for a configurable Obsidian vault as the agent's primary memory was closed "not planned" the same day ([memory-wiki docs](https://raw.githubusercontent.com/openclaw/openclaw/main/docs/plugins/memory-wiki.md); [obsidian-vault-maintainer SKILL.md](https://raw.githubusercontent.com/openclaw/openclaw/main/extensions/memory-wiki/skills/obsidian-vault-maintainer/SKILL.md); [openclaw#22958](https://github.com/openclaw/openclaw/issues/22958)). Community practice simply points `agents.defaults.workspace` or the wiki path inside an existing vault instead.

The alternatives market themselves relative to OpenClaw. Hermes Agent (NousResearch, **~253k stars**) is provider-agnostic with a one-command `hermes claw migrate` that imports OpenClaw's `SOUL.md`, memories, skills and keys, and pairs `MEMORY.md`/`USER.md` with FTS5 session search ([NousResearch/hermes-agent](https://github.com/NousResearch/hermes-agent)). NanoClaw (**30.9k stars**) is the only one built natively on Anthropic's Claude Agent SDK: each agent group runs in its own Linux container that "can only see what's explicitly mounted," has its own `CLAUDE.md` and memory, adds channels via `/add-<channel>` skills, and deliberately has no config files, with recurring jobs gated by scripts so the agent is not woken when there is no work ([qwibitai/nanoclaw](https://github.com/qwibitai/nanoclaw)). ZeroClaw (**33k stars**) is a Rust single binary with Anthropic among its providers, `claude setup-token` auth for Max users, 30+ channels, SQLite-plus-embeddings memory rather than Markdown, a `supervised` default autonomy mode and OS sandboxes ([zeroclaw-labs/zeroclaw](https://github.com/zeroclaw-labs/zeroclaw)). nanobot (HKUDS, **49k stars**) is a compact Python framework whose README names OpenAI-compatible APIs rather than Anthropic directly ([HKUDS/nanobot](https://github.com/HKUDS/nanobot)). Khoj (37.6k stars) is the older "AI second brain" with an Obsidian plugin and Claude among its models, but it is a search-and-chat product rather than an acting assistant ([khoj-ai/khoj](https://github.com/khoj-ai/khoj)). For Obsidian specifically, only OpenClaw ships an official vault-rendering mode; the rest treat the vault as a folder.

Anthropic's answer has been to absorb the harness pattern into Claude Code (**150.2k stars**, v2.1.296 on 9 October 2026) rather than ship a separate assistant ([anthropics/claude-code](https://github.com/anthropics/claude-code)). Channels, a research preview, define a channel as "an MCP server that pushes events into your running Claude Code session," two-way "like a chat bridge," with first-party Telegram, Discord and iMessage plugins: install `/plugin install telegram@claude-plugins-official`, `/telegram:configure <token>`, restart with `claude --channels plugin:telegram@claude-plugins-official`, pair with `/telegram:access pair <code>`, then lock with `/telegram:access policy allowlist`; events "only arrive while the session is open, so for an always-on setup you run Claude in a background process or persistent terminal" ([Claude Code channels docs](https://code.claude.com/docs/en/channels)). The Telegram plugin can send files up to 50 MB, edit messages for progress and download inbound photos, but has no message history because of the Bot API, and its default `pairing` policy replies to any stranger with a pairing code until switched to `allowlist` ([claude-plugins-official Telegram](https://github.com/anthropics/claude-plugins-official/tree/main/external_plugins/telegram)). Auto memory, the second piece, has Claude write four note types (`user`, `feedback`, `project`, `reference`) under `~/.claude/projects/<project>/memory/` with a `MEMORY.md` index of which only the **first 200 lines or 25 KB** load per session, a `modified` ISO timestamp stamped into frontmatter, and an `autoMemoryDirectory` setting that can relocate the folder, for instance into the vault ([Claude Code memory docs](https://code.claude.com/docs/en/memory)). Scheduling, the third piece, is three-tiered: `/loop` runs cron-like prompts inside an open session (minimum 1 minute, up to 50 tasks, recurring tasks expire after 7 days); Desktop scheduled tasks run on your machine with local file access and per-task permission modes, storing prompts at `~/.claude/scheduled-tasks/<task-name>/SKILL.md`; cloud Routines run on Anthropic infrastructure with a minimum one-hour interval, no local files, claude.ai connectors only, and no permission prompts ([scheduled-tasks docs](https://code.claude.com/docs/en/scheduled-tasks); [desktop-scheduled-tasks docs](https://code.claude.com/docs/en/desktop-scheduled-tasks); [routines docs](https://code.claude.com/docs/en/routines)). Remote Control, the fourth, mirrors a local `claude` session to claude.ai/code or the iOS/Android app so "your code execution and filesystem access stay on your machine," with local MCP servers intact; it requires a Pro/Max/Team/Enterprise login and the process to stay running ([Remote Control docs](https://code.claude.com/docs/en/remote-control)). Cowork, included on Pro ($20), Max 5x ($100) and Max 20x ($200), extends the same engine to non-developers with folder access, a built-in browser (26 August 2026) and scheduled tasks; the product page says a scheduled task "runs unattended, even with your laptop closed," which applies to cloud-side runs, while Desktop local tasks (the ones that can touch a vault) need the app open and the machine awake ([claude.com/product/cowork](https://claude.com/product/cowork); [desktop-scheduled-tasks docs](https://code.claude.com/docs/en/desktop-scheduled-tasks)). A long-open bug (filed 13 April 2026, still open 16 September) in which Cowork/Desktop scheduled tasks re-prompt for folder and connector permissions on every run despite "Always allow" is the main practical friction in this path ([claude-code issue #47180](https://github.com/anthropics/claude-code/issues/47180)).

The structural consequence for Obsidian users is simple: OpenClaw and Claude Code now converge on the same memory shape (a short curated index plus dated Markdown files plus a search tool), but Claude Code and Cowork operate directly on the local folder the vault lives in, and Claude Code's schedulers are the only unattended path where subscription billing is explicitly sanctioned ([routines docs](https://code.claude.com/docs/en/routines)).

## Vault memory converges on a small index, dated logs and nightly consolidation

Folder taxonomy matters less than most guides suggest; what every serious 2026 design shares is a small bootstrap file read first and an append-only log. Karpathy's "LLM Wiki" gist (created 4 April 2026, 5,000+ stars) is the most influential statement of the pattern: immutable `raw/` sources, an LLM-owned `wiki/` of entity, concept and summary pages, a schema document "named as CLAUDE.md for Claude Code," an `index.md` catalog the model "reads first when answering queries," and an append-only `log.md` with headings like `## [2026-04-02] ingest | Article Title`; "Obsidian is the IDE," the wiki is a git repo, and the index approach "works well at roughly 100 sources and hundreds of pages" before a local hybrid search tool such as qmd is needed ([Karpathy gist](https://gist.github.com/karpathy/442a6bf555914893e9891c11519de94f)). The most-starred implementation is `eugeniughelbur/obsidian-second-brain` (**4,732 stars**, created March 2026, v0.15 September 2026), a Claude Code plugin whose `--style wiki` layout adds `_CLAUDE.md`, `index.md`, `log.md`, `SOUL.md`, `CRITICAL_FACTS.md`, `raw/`, `wiki/`, `boards/` and `templates/`, and whose "AI-first rule" requires every note to carry a `## For future agent` preamble, rich frontmatter with `ai-first: true`, recency markers on external claims, verbatim source URLs, and confidence labels (`stated | high | medium | speculation`), on the stated rationale that "vault notes are designed for future agent retrieval, not human reading" ([obsidian-second-brain README](https://github.com/eugeniughelbur/obsidian-second-brain); [sample `_CLAUDE.md`](https://github.com/eugeniughelbur/obsidian-second-brain/blob/main/examples/sample-vault/_CLAUDE.md); [repo CLAUDE.md](https://github.com/eugeniughelbur/obsidian-second-brain/blob/main/CLAUDE.md)). `AgriciDaniel/claude-obsidian` (**15,461 stars**, created April 2026) is the engineering-heavy sibling: "based on Karpathy's LLM Wiki pattern," it keeps the product checkout separate from the vault, uses `inbox/`, `.raw/`, `wiki/` and `.vault-meta/`, ships 15 namespaced skills (`wiki-ingest`, `wiki-query`, `wiki-lint`, `wiki-fold`), and protects writes with a process-lifetime vault lock, journaled backups, atomic replacement and rollback, with parallel workers returning drafts that one orchestrator applies ([AgriciDaniel/claude-obsidian](https://github.com/AgriciDaniel/claude-obsidian)).

The second family is PARA-style productivity cascades. `ballred/obsidian-claude-pkm` (1,877 stars) uses `Daily Notes/`, a `Goals/` cascade from three-year to weekly, per-project folders each with its own nested `CLAUDE.md`, a tag taxonomy for priority/status/context, skills such as `/daily`, `/weekly`, `/push` (commit and push), agents like `inbox-processor` and `weekly-reviewer`, and a `.claude/` tree of `agents/`, `skills/`, `hooks/`, `rules/`, `output-styles/` and `settings.json` with hooks for "auto-commit on file writes, session init, skill discovery" ([ballred vault-template CLAUDE.md](https://github.com/ballred/obsidian-claude-pkm/blob/main/vault-template/CLAUDE.md); [ballred README](https://github.com/ballred/obsidian-claude-pkm)). `heyitsnoah/claudesidian` (2.6k stars) numbers its PARA folders `00_Inbox` through `06_Metadata` and lists the first pitfall newcomers hit: "Claude can't find notes unless you run it from the vault root" ([heyitsnoah/claudesidian](https://github.com/heyitsnoah/claudesidian)). Critics of PARA for agent memory argue it sorts by actionability rather than by memory lifetime and provenance; one essay states "PARA gets you started, then it breaks... your agent can't find anything in it" and adds a `Sources` folder for provenance, while an Obsidian forum thread proposes a `Working Context/` folder with one state file per active project read at session start ([wasita.net](https://wasita.net/blog/four-folders-wont-hold/); [forum.obsidian.md thread 112010](https://forum.obsidian.md/t/design-your-vault-for-ai-orientation-not-just-human-navigation/112010)). The third family makes memory itself atomic: `jrcruciani/obsidian-memory-for-ai` (v4.1) stores one typed fact per file under `memory/facts/{entity}/{predicate}.md`, moves superseded versions to history, keeps append-only `memory/events/YYYY-MM-DD/`, generates a `_views/bootstrap.md` read model loaded first, and explicitly has "no database, daemon, vector store, server, embeddings, or binary source of truth" ([jrcruciani/obsidian-memory-for-ai](https://github.com/jrcruciani/obsidian-memory-for-ai)). Reading across these kits, the recurring `CLAUDE.md` sections are identity and purpose, a folder map, a frontmatter schema and tag taxonomy, linking rules (wikilinks only, search before create, no links to nonexistent files), workflow commands, and prohibitions (no restructuring, no deletion, no invented facts, mark unknowns `TBD`).

Retrieval follows Anthropic's own description of Claude Code as "a hybrid model: CLAUDE.md files are naively dropped into context up front, while glob and grep fetch files just-in-time," which "avoids stale indexes" at the cost of slower exploration; the same essay notes that "folder hierarchies, naming conventions, and timestamps all provide important signals" ([Anthropic, Effective context engineering](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents)). The one quantified data point on when that stops being enough comes from obsidian-second-brain's author on a ~2,350-note vault: keyword recall@10 of 1.0 but **paraphrased-question recall@10 of 77%**, with non-English recall@5 rising from 13% to 63% after adding a local multilingual embedding model (Ollama `bge-m3`) fused with keyword search; the caveat is that "the semantic index doesn't update itself" and must be rebuilt ([obsidian-second-brain README](https://github.com/eugeniughelbur/obsidian-second-brain)). Other retrieval bridges include Smart Connections (5.5k stars, local embeddings in `.smart-env/`) exposed to Claude through a small MCP server that loads ~3,249 embeddings in 2–3 seconds and answers in 100–200 ms but needs a restart to see new notes, and `basic-memory` (4.1k stars), a Markdown-plus-SQLite MCP server with an observations/relations schema ([brianpetro/obsidian-smart-connections](https://github.com/brianpetro/obsidian-smart-connections); [dan6684/smart-connections-mcp](https://github.com/dan6684/smart-connections-mcp); [basicmachines-co/basic-memory](https://github.com/basicmachines-co/basic-memory)). The honest conclusion is that under roughly 1–3k notes an index file plus ripgrep and the Obsidian CLI is sufficient and avoids stale-index failure modes; the 23-point paraphrase gap is the concrete reason to add a local hybrid layer as the vault grows.

Consolidation is where the ecosystems agree most tightly. Claude Code's auto memory enforces a loop by measuring `MEMORY.md` after each write and reminding Claude to "keep one line per entry, move detail into topic files, and merge or drop stale entries" ([Claude Code memory docs](https://code.claude.com/docs/en/memory)). OpenClaw's memory flush writes to the daily note before compaction and its Dreaming job promotes gated candidates into `MEMORY.md`, with the guidance to "record the action boundary, not just the fact: approval requirements, expiry, safe-to-act timing" because "Memory does not enforce policy" ([OpenClaw memory docs](https://raw.githubusercontent.com/openclaw/openclaw/main/docs/concepts/memory.md)). Obsidian-centric kits run the same loop on cron: obsidian-second-brain schedules a morning brief at 8 AM, nightly consolidation at 10 PM, a weekly review Friday 6 PM and a health audit Sunday 9 PM, plus a PostCompact background agent restricted to `Read,Write,Edit,Glob,Grep` that ships disabled because it runs `--dangerously-skip-permissions`; `CodyLiska/obsidian-llm-memory` adds a `pre-compact.sh` checkpoint hook and claims only ~3,000 tokens of index load at startup ([obsidian-second-brain README](https://github.com/eugeniughelbur/obsidian-second-brain); [CodyLiska/obsidian-llm-memory](https://github.com/CodyLiska/obsidian-llm-memory)). Anthropic's API-level memory tool (`memory_20250818`) is the equivalent primitive for custom harnesses: client-side file operations under a `/memories` prefix that the handler maps to real storage (and must guard against path traversal), auto-prompted with "ALWAYS VIEW YOUR MEMORY DIRECTORY BEFORE DOING ANYTHING ELSE... ASSUME INTERRUPTION," and paired with context editing; Anthropic reports **39% improvement** on an internal agentic-search eval for memory plus context editing and an **84% token reduction** in a 100-turn eval from clearing stale tool results ([Memory tool docs](https://platform.claude.com/docs/en/agents-and-tools/tool-use/memory-tool); [claude.com context-management blog](https://claude.com/blog/context-management)). Two hard numbers should shape any index design: Claude Code's 200-line/25 KB load cap, and OpenClaw's truncation of the injected `MEMORY.md` copy when it exceeds the bootstrap budget.

## Voice is input-only first-party, phones go through Tailscale, and schedulers come in three tiers

Claude Code gained first-party voice in 2026, but only as dictation: `/voice` enables push-to-talk or tap modes, "streams your recorded audio to Anthropic's servers for transcription," requires a claude.ai login and a local microphone, "does not work in cloud sessions or SSH sessions," and does not read replies aloud ([Voice dictation docs](https://code.claude.com/docs/en/voice-dictation)). Every "Jarvis talks back" build therefore layers a third-party stack on Claude Code's hooks or an MCP server. `mbailey/voicemode` (1.4k stars) is the most mature: an MCP `converse` tool with local whisper.cpp or OpenAI STT and local Kokoro or OpenAI TTS, installable as a plugin, able to "run entirely locally" ([mbailey/voicemode](https://github.com/mbailey/voicemode)). `ethanplusai/jarvis` (853 stars, March 2026) is the most-starred voice-first Jarvis: Chrome Web Speech STT, Fish Audio cloud TTS ("the one thing you pay for"), one persistent `claude -p` process billed to a subscription, AppleScript to answer permission prompts, and `--dangerously-skip-permissions` by default ([ethanplusai/jarvis](https://github.com/ethanplusai/jarvis)). Fully local stacks exist for Linux (`claude-talk`: whisper.cpp in, Piper or Kokoro out, openwakeword wake words, ~0.9 s STT and 0.8 s to first audio after warm-up) and Apple Silicon (`jvosloo/claude-voice`: Parakeet STT, Kokoro TTS via mlx-audio, narrate mode summarizing via a local Ollama model, all wired through `Stop`, `Notification` and `PermissionRequest` hooks) ([jjacke13/claude-talk](https://github.com/jjacke13/claude-talk); [jvosloo/claude-voice](https://github.com/jvosloo/claude-voice)). NetworkChuck's `claude-phone` (319 stars) even puts Claude Code behind a SIP extension with Whisper and ElevenLabs so "your AI can call you" ([theNetworkChuck/claude-phone](https://github.com/theNetworkChuck/claude-phone)). On the Obsidian side, meeting and voice-note capture is handled by plugins such as Vocalog (Groq/OpenAI Whisper into daily notes with transcripts preserved) and by `silverstein/minutes` (1.5k stars), a local-first Granola alternative whose 34 MCP tools let Claude Code query meetings saved as Markdown-plus-YAML; none of the fetched projects combines wake word, local STT/TTS, Obsidian memory and Claude Code in one repo, so builders assemble these parts themselves ([muminkoykiran/Vocalog](https://github.com/muminkoykiran/Vocalog); [silverstein/minutes](https://github.com/silverstein/minutes)).

Mobile access has three patterns. Anthropic's Remote Control and Channels cover most of what DIY Telegram bots used to do, but the DIY pattern persists for Linux VPS hosts without a microphone and for vault-specific logic. The canonical DIY chain is phone → Termius or Termux → Tailscale → Mac mini → tmux → Claude Code, or `buckle42/claude-code-remote` (155 stars), which adds a ttyd web terminal and a FastAPI voice wrapper bound only to the Tailscale IP, with the author's warning that it "gives full shell access to the Mac" ([buckle42/claude-code-remote](https://github.com/buckle42/claude-code-remote); [agentic-engineer.com](https://agentic-engineer.com/blog/2026-09-14-run-claude-code-from-your-phone-tmux-tailscale)). Obsidian Mobile gets its own relays: the "Claude Anywhere" community plugin streams a Mac's Claude Code session into Obsidian on iOS/Android over Tailscale with the vault synced separately, and "Vault Companion for Claude" wraps the Agent SDK on the Mac ([Obsidian forum: Claude Anywhere](https://forum.obsidian.md/t/claude-anywhere-run-claude-code-from-obsidian-mobile/110497); [Vault Companion listing](https://community.obsidian.md/plugins/vault-companion-for-claude)). Anthropic's Dispatch research preview (March 2026) lets a phone drive a vault through Cowork's permissions ([xda-developers Dispatch](https://www.xda-developers.com/run-entire-obsidian-vault-from-phone-with-claude-dispatch/)). Hardware is overwhelmingly a Mac mini kept awake with `pmset`/caffeinate and launchd, or a $5–6/month VPS for Linux bots; Raspberry Pi appears only as a thin voice satellite ([Hostinger Mac mini guide](https://www.hostinger.com/tutorials/openclaw-mac-mini/); [composio-community/secure-openclaw](https://github.com/composio-community/secure-openclaw)).

Proactive automation tracks where the vault lives. Anthropic's comparison table is explicit: cloud Routines need no machine but see no local files and cannot use `claude mcp add` servers (only claude.ai connectors or a committed `.mcp.json`), run "without stopping for approval," and cost subscription usage; Desktop tasks see local files, run only while the app is open and the computer awake, and do one catch-up run for misses within 7 days ("a task scheduled for 9am might run at 11pm"); `/loop` inherits the session's MCP and permissions ([desktop-scheduled-tasks docs](https://code.claude.com/docs/en/desktop-scheduled-tasks); [routines docs](https://code.claude.com/docs/en/routines)). Anthropic names "morning briefings that pull from your calendar and inbox" as the headline Desktop use case ([desktop-scheduled-tasks docs](https://code.claude.com/docs/en/desktop-scheduled-tasks)). Because Routines cannot read a local vault unless it lives in a GitHub repository the routine clones, vault-centric builds stay on local schedulers: `smixs/agent-second-brain` runs a cron ticker in a second isolated Claude session "so reminders don't interrupt chat," `enochko/jarvis` runs an overnight orchestrator with per-task `curfew` and hourly-quota backoff "to protect daytime quota," and `claude-ops` (543 stars) runs nine launchd services from a 2-minute briefing pre-warm to a 30-minute Haiku memory extractor and a weekly competitor sweep ([smixs/agent-second-brain](https://github.com/smixs/agent-second-brain); [enochko/jarvis](https://github.com/enochko/jarvis); [claude-ops](https://github.com/Lifecycle-Innovations-Limited/claude-ops)). OpenClaw users split the same work between the heartbeat (ambient "anything need attention?" turns, each a full agent turn, best run on a cheap model with `isolatedSession` and `lightContext`) and exact-time automations ("recurring tasks, such as inbox reviews, calendar sweeps, or scheduled check-ins, should be separate automation jobs") ([heartbeat docs](https://raw.githubusercontent.com/openclaw/openclaw/main/docs/gateway/heartbeat.md)). Capture automations round this out: the "Ingester" plugin watches a Web Clipper folder and runs `claude "/ingest <path>"` in tmux, and several builds pull Granola meeting notes into the vault nightly ([Ingester plugin](https://community.obsidian.md/plugins/ingester); [Crystal Widjaja](https://crystalwidjaja.substack.com/p/my-chief-of-chores-via-claude-code)). n8n, Make and Zapier are essentially absent from the Claude-plus-Obsidian builds found; Claude Code skills plus OS schedulers fill the orchestration role.

Tool connections converge on a minimum of **Gmail plus Google Calendar plus the vault**, with Slack/WhatsApp/iMessage/Telegram as message sources and Granola, Linear, Todoist or Notion as optional context. `claude-chief-of-staff` (439 stars, by Ada's CEO) requires Gmail and Calendar MCP servers and claims morning inbox processing fell from ~90 minutes to ~5 ([mimurchison/claude-chief-of-staff](https://github.com/mimurchison/claude-chief-of-staff)). A notable trend is builders preferring CLIs for write actions, `gog` for sending mail, `wacli` for WhatsApp, `imsg`, `signal-cli` and the Obsidian CLI, because MCP OAuth scopes are often read-only and CLIs carry less overhead; `claude-ops` keeps `.mcp.json` intentionally empty so servers start on demand ([claude-ops](https://github.com/Lifecycle-Innovations-Limited/claude-ops)). Home Assistant has an official Anthropic conversation integration and an MCP Server integration but shows up rarely in Obsidian-Jarvis builds ([HA Anthropic integration](https://home-assistant.io/integrations/anthropic)).

Model choice in October 2026 is straightforward on paper: OpenClaw's provider docs list `anthropic/claude-opus-5-5` as the default for fresh setups, with Sonnet 5.5 for cost, Haiku 5.5 for heartbeats and consolidation, and quoted API prices (per million input/output tokens) of **Haiku 5.5 $0.10/$0.50, Sonnet 5.5 $2/$10, Opus 5.5 $4/$20, Opus 5 $5/$25, Fable 5.1 and Mythos 5 $10/$50**; these figures come from OpenClaw's docs rather than Anthropic's pricing page and should be verified before relying on them ([OpenClaw Anthropic provider docs](https://raw.githubusercontent.com/openclaw/openclaw/main/docs/providers/anthropic.md)). Billing is where 2026 was turbulent, and it decides which harness is viable. Anthropic's Agent SDK docs state that "unless previously approved, Anthropic does not allow third party developers to offer claude.ai login or rate limits for their products, including agents built on the Claude Agent SDK" ([Agent SDK overview](https://code.claude.com/docs/en/agent-sdk/overview)). Press coverage reports an email telling subscribers that from 4 April 2026 subscription limits could no longer back third-party harnesses such as OpenClaw, OpenCode, NanoClaw and Cline, with pay-as-you-go instead ([TechCrunch](https://techcrunch.com/2026/04/04/anthropic-says-claude-code-subscribers-will-need-to-pay-extra-for-openclaw-support/)). A separate plan to move Agent SDK and `claude -p` usage onto a monthly credit of $20 (Pro), $100 (Max 5x) and $200 (Max 20x) on 15 June 2026 was paused on the day; OpenClaw's docs summarize the current state as "Agent SDK and `claude -p` usage currently draw from the signed-in subscription's limits" while warning that "Anthropic can change this behavior without an OpenClaw release" and recommending API keys "for shared automation" ([OpenClaw Anthropic provider docs](https://raw.githubusercontent.com/openclaw/openclaw/main/docs/providers/anthropic.md); [TechTimes](https://www.techtimes.com/articles/317625/20260602/anthropic-ends-subscription-subsidy-agents-june-15-credit-pool-replaces-flat-rate-access.htm)). The help center confirms the mechanics that matter for a daemon: Pro and Max have a five-hour session limit and a weekly limit shared between Claude and Claude Code, setting `ANTHROPIC_API_KEY` switches Claude Code to API billing, and Max's included API credits cannot be spent in Claude Code ([support.claude.com](https://support.claude.com/en/articles/11145838-using-claude-code-with-your-pro-or-max-plan)). The community's adaptation is visible in code: smixs's bot deliberately types into a persistent interactive session and ships a CI guard that fails the build if `claude -p` appears, while Smart Composer warns that users who logged a Claude subscription into a third-party plugin "reported bans" ([smixs/agent-second-brain](https://github.com/smixs/agent-second-brain); [glowingjade/obsidian-smart-composer](https://github.com/glowingjade/obsidian-smart-composer)). Cost anecdotes for API-billed 24/7 agents range from "$50 to $500+ a month" to "$800 to $1,500 a month," and Steinberger's own OpenClaw bill has been estimated at $10k–20k a month, which is why subscription-backed Claude Code daemons dominate personal builds ([DEV reality check](https://dev.to/thegdsks/i-tried-the-free-ai-agent-with-124k-github-stars-heres-my-500-reality-check-2885); [Silicon Republic](https://www.siliconrepublic.com/business/peter-steinberger-openclaw-moltbot-moltbook-ai-openai-personal-agents)). Routines and Desktop tasks "draw down subscription usage the same way interactive sessions do," making Claude Code's own schedulers the only unattended path where subscription billing is explicitly sanctioned ([routines docs](https://code.claude.com/docs/en/routines)).

## OpenClaw's exposed gateways wrote the security playbook; vault pitfalls are mostly sync and links

OpenClaw became the canonical agent-security case study within weeks of going viral. Censys tracked growth "from approximately 1,000 to over 21,000 publicly exposed instances between 25 and 31 January 2026," a later fingerprint analysis found 63,070 live instances by late March, and other sweeps report figures from 10,000 to 135,000+ depending on method, so ranges rather than single numbers are appropriate ([conscia](https://conscia.com/blog/the-openclaw-security-crisis/); [CSA research note](https://labs.cloudsecurityalliance.org/wp-content/uploads/2026/06/CSA_research_note_openclaw_indirect_prompt_injection_20260613-csa-styled.pdf)). Exposed instances leaked Anthropic API keys, Telegram bot tokens and full chat histories stored in plaintext; **CVE-2026-25253 (CVSS 8.8)** allowed a malicious web page to leak the auth token and execute commands on the host until 2026.1.29, and CVE-2026-22708 covered unsanitized web content entering the context window, where persistent memory makes injected instructions latent and time-delayed ([adversa.ai](https://adversa.ai/blog/openclaw-security-101-vulnerabilities-hardening-2026/); [DigitalOcean](https://www.digitalocean.com/resources/articles/openclaw-security-challenges)). The skill marketplace proved polluted: Koi Security found 341 malicious skills among 2,857 audited on ClawHub, and Snyk's audit of 3,984 skills found **36% with flaws**, 76 with confirmed malicious payloads and 7.1% leaking credentials in plaintext ([repello teardown](https://repello.ai/blog/malicious-openclaw-skills-exposed-a-full-teardown); [particula](https://particula.tech/blog/openclaw-security-crisis-malicious-ai-agents)). OpenClaw's current posture is correspondingly conservative: loopback-only gateway on host installs, pairing codes for unknown DM senders, mention-gated groups, Docker sandboxing of non-main sessions, `tools.fs.workspaceOnly`, an `openclaw security audit` command with auto-fix, and the admission that sandboxing "is not a perfect security boundary" and file-type checks "are not a secret scanner. Keep sensitive files outside the agent-readable filesystem" ([OpenClaw security docs](https://raw.githubusercontent.com/openclaw/openclaw/main/docs/gateway/security/index.md); [sandboxing docs](https://raw.githubusercontent.com/openclaw/openclaw/main/docs/gateway/sandboxing.md); [start/openclaw.md](https://raw.githubusercontent.com/openclaw/openclaw/main/docs/start/openclaw.md)).

Anthropic's own surfaces carry equivalent warnings that an Obsidian builder must read before going unattended. Channels relay permission prompts to chat, so "anyone who can reply through the channel can approve or deny tool use in your session, so only allowlist senders you trust with that authority," and iMessage self-texting bypasses the gate entirely ([channels docs](https://code.claude.com/docs/en/channels)). Routines run with no permission prompts and "Claude can use every tool from an included connector, including writes, without asking," so connectors should be stripped to what the routine needs; API fire payloads arrive wrapped in `<routine-fire-payload>` tags labelled untrusted ([routines docs](https://code.claude.com/docs/en/routines)). The memory docs state the rule that governs all vault governance: CLAUDE.md and auto memory are "context, not enforced configuration. To block an action regardless of what Claude decides, use a PreToolUse hook instead," and Cowork sessions skip user-scope imports and symlinked `~/.claude/CLAUDE.md` entries pointing outside the working directory ([Claude Code memory docs](https://code.claude.com/docs/en/memory)). Every build that runs unattended hits the same trade-off, either stalls on permission prompts or `--dangerously-skip-permissions`, which the docs sanction "only in environments you trust"; the SDK-based `NanoClaw` and the Desktop tasks' optional isolated git worktree per run are the two mechanisms that make the convenient choice safer ([channels docs](https://code.claude.com/docs/en/channels); [qwibitai/nanoclaw](https://github.com/qwibitai/nanoclaw); [desktop-scheduled-tasks docs](https://code.claude.com/docs/en/desktop-scheduled-tasks)). Practices seen across primary sources are consistent: sender allowlists on every channel, secrets in chmod-600 `.env` files or Doppler/Keychain and never in the vault, `.claudeignore` plus `--allowedTools` and write-directory restrictions, Tailscale-only binding, read-only connector scopes first, and local STT/TTS when audio must not leave the machine ([enochko/jarvis](https://github.com/enochko/jarvis); [claude-ops](https://github.com/Lifecycle-Innovations-Limited/claude-ops); [buckle42/claude-code-remote](https://github.com/buckle42/claude-code-remote)). For the vault specifically, the Local REST API's key "authorizes remote modification of the Obsidian vault," so keep it in an environment variable, never on a command line that lands in shell history, and never rebind the plugin from 127.0.0.1 ([obsidian-mcp-ts SECURITY.md](https://glama.ai/mcp/servers/@duquesnay/obsidian-mcp-ts/blob/f82442b0ab6a2e409e430157d27069ab0255cbdd/SECURITY.md)). The deeper design implication is that because memory is Markdown the agent both reads and writes, a prompt injection arriving by email or web page can be stored today and triggered next week; that argues for an agent-writable memory folder separated from the human's main notes (or OpenClaw's isolated wiki) with diffs reviewed through git.

The vault-specific pitfalls are more mundane but hit everyone. Obsidian Sync "skips hidden files," so `.claude/` configuration, skills and auto memory never reach a second device; the workaround is a visible `_claude/` folder with per-device symlinks and `settings.local.json` excluded because it holds device-specific permissions ([maulmota/claude-code-obsidian-sync](https://github.com/maulmota/claude-code-obsidian-sync)). `.obsidian/workspace.json` changes constantly and shows up as a conflict on every git pull unless `git rm --cached` and gitignored; Syncthing produces `.sync-conflict` files when an agent edits a note open elsewhere ([obsidian-git issue #114](https://github.com/denolehov/obsidian-git/issues/114); [SSD Nodes guide](https://www.ssdnodes.com/learn/claude-code-with-obsidian-vault)). A permission-rule footgun specific to Claude Code: `Write(...)` and `Glob(...)` path rules in `settings.json` are "accepted but never consulted by file permission checks," so file-write restrictions must be written as `Edit(...)` rules ([SSD Nodes guide](https://www.ssdnodes.com/learn/claude-code-with-obsidian-vault)). Quality drift follows predictable lines, Markdown links instead of wikilinks, invented link targets, duplicate notes, logs landing in a different folder each day, and agents "humanizing" or restructuring content, which the kits counter with search-before-create, a ban on links to nonexistent files, and explicit prohibitions ([Taming the Archivist](https://medium.com/@kaiqueperezz/taming-the-archivist-guardrails-for-ai-memory-in-obsidian-8012944cacf0); [eugeniughelbur repo CLAUDE.md](https://github.com/eugeniughelbur/obsidian-second-brain/blob/main/CLAUDE.md)). Stale memory is the subtler failure: plain text "can hold an outdated assumption as easily as a current decision," and agents end up "treating a stored preference as permission," which is why `as_of`, `confidence` and `status: active|superseded` frontmatter and nightly lint passes recur across the better kits ([Zchmael Substack](https://zchmael.substack.com/p/how-i-keep-my-ai-agents-obsidian)). Platform caveats: native Windows is read-only in `claude-obsidian` (writes need WSL), Agent SDK plugins cannot run on mobile, Claude Code on Bun ignores the macOS keychain so self-signed MCP endpoints need `NODE_EXTRA_CA_CERTS`, and a vault with thousands of notes "hits the same limits as a large repository" ([AgriciDaniel/claude-obsidian](https://github.com/AgriciDaniel/claude-obsidian); [aaronsb/obsidian-mcp-plugin](https://github.com/aaronsb/obsidian-mcp-plugin); [Starmorph guide](https://blog.starmorph.com/blog/obsidian-claude-code-integration-guide)). Notably, no confirmed report was found of Obsidian's own file watcher corrupting files during concurrent local Claude Code edits; the conflict reports all involve multi-device sync tools.

## Recommended reference architecture: Claude Code as daemon over a git-backed vault

The configuration that best matches the evidence in October 2026 treats Claude Code as the harness, the vault as co-owned memory, and Anthropic's first-party surfaces as the channel and scheduler layer, with OpenClaw reserved for people who need twenty chat channels or a heartbeat more than they need Obsidian fidelity. The host is a Mac mini (or any always-on machine) reachable only over Tailscale, with FileVault on and no public ports ([mager.co](https://mager.co/blog/2026-02-22-openclaw-mac-mini-tailscale/)). The vault is a git repository (Obsidian Git or a `/push` skill) with `.obsidian/workspace.json` and `.trash/` ignored, so every agent edit is reviewable and reversible ([Reitz essay](https://github.com/kennethreitz/kennethreitz.org/blob/main/data/essays/2026-03-06-obsidian_vaults_and_claude_code.md); [obsidian-git issue #114](https://github.com/denolehov/obsidian-git/issues/114)). Its layout borrows the LLM-wiki split for provenance and the memory-tiered split for lifetime: a root `CLAUDE.md` under 200 lines; `.claude/` holding `rules/` (path-scoped conventions), `skills/`, `hooks/` and `settings.json`; `index.md` and `log.md` at the root; `Daily/` for human and agent daily notes written via `obsidian daily:append`; `memory/` as the only folder the agent writes freely (topic notes plus a `MEMORY.md` index capped near 200 lines, with `autoMemoryDirectory` pointed here so Claude Code's own auto memory lands in the vault); `raw/` for immutable clippings and transcripts; `wiki/` for agent-maintained entity and concept pages; and `Archive/` denied to the agent ([Karpathy gist](https://gist.github.com/karpathy/442a6bf555914893e9891c11519de94f); [Claude Code memory docs](https://code.claude.com/docs/en/memory)). Every agent-written note carries `type`, `created`, `modified` or `as_of`, `source`, `confidence` and `status`, and a `.base` file over `type: decision` and `status: active` gives the human a live dashboard without Dataview ([kepano obsidian-bases SKILL.md](https://github.com/kepano/obsidian-skills/blob/main/skills/obsidian-bases/SKILL.md)).

The brain is Claude Code launched at the vault root with `obsidian-skills` installed as a plugin and the Obsidian CLI enabled, so syntax comes from the skills, cheap reads from ripgrep, and index-aware writes (daily notes, properties, backlink checks, orphan sweeps) from the CLI ([kepano/obsidian-skills](https://github.com/kepano/obsidian-skills); [kepano obsidian-cli SKILL.md](https://github.com/kepano/obsidian-skills/blob/main/skills/obsidian-cli/SKILL.md)). Permissions follow the posture the kits converge on, expressed in `.claude/settings.json` roughly as `{"permissions": {"allow": ["Read", "Glob", "Grep"], "ask": ["Bash(mv:*)", "Bash(git push:*)"], "deny": ["Bash(rm:*)", "Edit(./Archive/**)", "Edit(./.obsidian/**)"]}}`, using `Edit(...)` rather than `Write(...)` for file rules and a `PreToolUse` hook on `Edit|Write` that rejects paths outside `memory/`, `Daily/`, `wiki/` and `raw/` for unattended runs, because prose in `CLAUDE.md` is advisory and only hooks enforce ([Vizzuality permissions reference](https://github.com/Vizzuality/claude-code-vault/blob/main/07.1%20Permissions.md); [hooks guide](https://code.claude.com/docs/en/hooks-guide); [Claude Code memory docs](https://code.claude.com/docs/en/memory)). A `Stop` or `PostToolUse` hook auto-commits, and a `PreCompact` hook writes a checkpoint to today's daily note, reproducing OpenClaw's memory flush with Claude Code primitives ([ballred README](https://github.com/ballred/obsidian-claude-pkm); [CodyLiska/obsidian-llm-memory](https://github.com/CodyLiska/obsidian-llm-memory)). The `CLAUDE.md` itself should contain the six sections every kit converges on (identity and timezone, folder map, frontmatter schema, linking rules, workflow commands, prohibitions) and the three lines that prevent the most damage: use `[[wikilinks]]` and never link to a file that does not exist; search before creating; mark unknowns `TBD` and never invent facts, dates or relationships ([eugeniughelbur sample `_CLAUDE.md`](https://github.com/eugeniughelbur/obsidian-second-brain/blob/main/examples/sample-vault/_CLAUDE.md); [xda-developers](https://www.xda-developers.com/added-one-thing-to-claude-obsidian-setup-and-wikilinks-stopped-breaking/)).

The surface layer is Anthropic-first. A persistent `claude --channels plugin:telegram@claude-plugins-official` session in tmux, with `/telegram:access policy allowlist` set immediately, gives chat access and permission relay to one trusted sender; Remote Control from the same session gives the phone app full steering with execution kept local ([channels docs](https://code.claude.com/docs/en/channels); [Remote Control docs](https://code.claude.com/docs/en/remote-control)). Proactivity splits by data locality: Desktop scheduled tasks (or launchd calling the vault session) run the 8 AM morning brief that reads the calendar and inbox connectors and writes to today's daily note, the 10 PM consolidation that promotes `Daily/` items into `memory/` and `wiki/` on a branch for review, and a Sunday health audit for broken links, orphans and stale `as_of` dates; cloud Routines are reserved for jobs that need no vault files, such as a Slack-to-Linear sweep, with connectors trimmed to the minimum because they run without prompts ([desktop-scheduled-tasks docs](https://code.claude.com/docs/en/desktop-scheduled-tasks); [routines docs](https://code.claude.com/docs/en/routines); [obsidian-second-brain README](https://github.com/eugeniughelbur/obsidian-second-brain)). Voice is dictation into the phone (Telegram voice notes transcribed locally or by Deepgram/Whisper) for the always-on host, and `voicemode` with local Whisper and Kokoro on the desk machine for spoken replies; `/voice` is fine at the keyboard but cannot serve a headless box ([Voice dictation docs](https://code.claude.com/docs/en/voice-dictation); [mbailey/voicemode](https://github.com/mbailey/voicemode)). Models: Opus 5.5 or Sonnet 5.5 for the interactive session, Haiku 5.5 (or a local Ollama model) for consolidation and any heartbeat-like polling, and a claude.ai subscription rather than an API key as long as everything runs through Claude Code's own session and schedulers; switch to an API key only for a shared or containerized deployment where the terms require it ([OpenClaw Anthropic provider docs](https://raw.githubusercontent.com/openclaw/openclaw/main/docs/providers/anthropic.md); [Agent SDK overview](https://code.claude.com/docs/en/agent-sdk/overview)). Add a local hybrid search layer (obsidian-second-brain's Ollama `bge-m3` index, `basic-memory`, or qmd) only once paraphrase recall visibly degrades, and keep private folders out of any cloud embedding endpoint with an exclusion list ([obsidian-second-brain README](https://github.com/eugeniughelbur/obsidian-second-brain)).

## Conclusion

The most important shift of 2026 is that the "harness" layer stopped being the differentiator. Once Claude Code gained channels, Markdown auto memory, schedulers and phone mirroring, and once Anthropic made clear that subscriptions may back only its own surfaces, the rational Claude-plus-Obsidian design became a thin arrangement of first-party primitives around a well-governed folder, with OpenClaw's role reduced to a reference for file conventions and to deployments that genuinely need its channel breadth. What now separates good builds from bad ones is vault governance rather than plumbing: a short root contract, an index capped at the 200-line load limit, dated logs consolidated nightly, frontmatter that records when a fact was true and how confident the agent was, writes confined by hooks rather than prose, and git as the audit trail. The Obsidian CLI and Bases quietly made the vault a queryable database for agents without a server, which is why index-plus-grep remains defensible far longer than the RAG-first instinct suggests.

The open problems are equally clear. Billing policy for headless Claude use has changed direction three times in six months and will change again, so any build should keep its brain behind a single swappable invocation. Prompt injection stored in persistent memory has no fix, only containment, which argues for an agent-writable folder separate from the human's notes and for review before promotion. And the first-party stack still has gaps a Jarvis cannot ignore: no read-aloud voice, no vault access from cloud Routines, research-preview status on Channels, and a permission re-prompt bug in Cowork's scheduler. Expect the next year's progress to come from Anthropic closing those gaps rather than from new harnesses, and design the vault so that it does not care which one wins.
